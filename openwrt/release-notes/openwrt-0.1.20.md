# Обход для OpenWrt 0.1.20

Исправления фильтрации DNS, резервирования и перезапуска службы.
Сетевое ядро остаётся **1.13.21-obhod.5**; выпуск Windows не меняется.

## Исправлено

- При включённом общем DNS выбранные домены проверяются настроенным резолвером
  до выдачи FakeIP. Блокировки, пустые ответы и DNS-отказы сохраняются; сбой
  проверки не разрешает подключение через FakeIP. Исходное доменное имя
  по-прежнему передаётся прокси.
- Новый режим **Основной и резервные** начинает запрос с первого DNS и
  переключается только при транспортной ошибке, тайм-ауте или повреждённом
  ответе. Корректная блокировка основного не отменяется резервным.
- Для DNS по имени требуется явный протокол. Например, адрес DoT нужно вводить
  как `tls://dns.example.com`; голое имя могло ошибочно использоваться как UDP.
- Сохранение настроек, restart/reload и восстановление ядра не возвращают
  dnsmasq на публичные DNS. Пока служба включена, длительный сбой отображается
  как ошибка; прежний DNS восстанавливается при явном выключении.
- Команды init сериализованы с применением настроек. Исправлены гонки позднего
  DNS apply при остановке, сохранение намерения включения и наследование
  блокировок фоновым наблюдателем.
- Диагностика проверяет доступность обработчика фильтрации. Подготовка компонента
  DNS доступна и для одиночного сервера.

## Обновление

Поддерживаются OpenWrt 24.10/opkg и 25.12/apk. Подключения, правила и выбранные
DNS сохраняются. Существующие режимы single/parallel/balanced автоматически
не меняются; для стабильной политики фильтрации выберите **Основной и резервные**
и задайте резервные с теми же правилами блокировки.

Перед обновлением сохраните резервную копию `/etc/obhod`, `/etc/config/obhod`
и `/etc/config/dhcp`. Используйте штатный обновлятор либо установщик этого
релиза. Необходимый `ucode-mod-socket` стандартный установщик получает заранее;
после обновления старого приложения компонент подготавливается перед первым
запуском настроенного DNS. Для этого нужен доступ к репозиторию OpenWrt.

Уже открытые соединения и DNS-кэш устройств могут сохраняться до истечения TTL;
после обновления переподключите Wi-Fi или перезапустите браузер.

## Проверки и ограничения

Проверены Node.js, LuCI, реальные OpenWrt UCI/ucode, APK/IPK, DNS UDP/TCP,
сохранение блокировок и восстановление службы. Подробности — `VALIDATION.md`.
Два последовательных перезапуска также проверены на физическом ARM64-роутере.

Клиентский DoH/DoT, другой VPN или Private Relay могут обходить DNS роутера.
DNS-фильтрация не гарантирует удаление рекламы, загружаемой с того же домена,
что и основной контент. Глобального сетевого kill switch нет: удержание
управляемого DNS при сбое не блокирует все возможные прямые соединения.
