# Соединения и восстановление OpenWrt

Изменения проверены 3 ноября 2026 года. Они входят в OpenWrt 0.1.17 и совместимое ядро `1.13.21-obhod.4`.

## Что перенесено и адаптировано из Podkop

Изучена ревизия Podkop `c654bf5da75309754e3fb63b9441981db65fff68`.
Использованы архитектурные подходы; реализация Обхода написана отдельно.

| Подход | Реализация Обхода | Проверка |
| --- | --- | --- |
| Сравнение конфигурации перед заменой | Семантически одинаковый профиль сохраняется без перезапуска sing-box и dnsmasq и без записи настроек во flash | На роутере SHA-256 профиля и PID не изменились |
| Проверенная конфигурация и временный файл | Существующая транзакция RPC проверяет кандидат ядром до атомарной замены; пропуск перезапуска дополнительно требует совпадения настроек и файлов подготовки текущего запуска | Изменение файлов приложения исключает ошибочный пропуск перезапуска |
| Мониторинг возвращения WAN через procd | События настроенных сетей объединяются с задержкой 2 с; перед восстановлением проверяется текущее состояние интерфейса и службы | Работающий процесс сохраняется, выключенный пользователем не запускается, параллельный apply защищён блокировкой |
| Кэш FakeIP и внешних списков в RAM | Существующий кэш sing-box сохранён; новая проверка подтверждает запуск без сервера списков | Сохраняются JSON/SRS и соответствие FakeIP после перезапуска; ошибочное обновление не заменяет рабочий набор |

Источники Podkop: [запуск и сохранение конфигурации](https://github.com/itdoginfo/podkop/blob/c654bf5da75309754e3fb63b9441981db65fff68/podkop/files/usr/bin/podkop),
[мониторинг сетевых событий](https://github.com/itdoginfo/podkop/blob/c654bf5da75309754e3fb63b9441981db65fff68/podkop/files/etc/init.d/podkop).

У procd `.*` означает сопоставление по префиксу: суффикс `.up` после него
не ограничивает событие подъёмом интерфейса. Поэтому Обход проверяет
`network.interface.<имя>.status.up` перед восстановлением. Это учитывает
изменения состояния за время задержки события.
[Исходник procd, функция trigger_match](https://github.com/openwrt/procd/blob/master/service/trigger.c).

## Ускорение явных IP-маршрутов

Выбранные CIDR проверяются до sniffing. Это позволяет SSH/SMTP и другим
соединениям, где сервер первым отправляет данные, начинать работу без
ожидания содержимого от клиента. DNS, восстановленное из FakeIP имя,
политика приватных адресов и запрет QUIC сохраняют прежний приоритет.
Правила программ Windows и Windows-генератор этим изменением не затронуты.

Изменение применяется к новым конфигурациям и к runtime-копиям старых
профилей. Сохранённый профиль на роутере не переписывается миграцией.

Локальный тест настоящего ядра с HTTP-прокси и сервером, который первым
передаёт приветствие: **1009 мс → 3 мс**. Это проверка устранения тайм-аута
sniffing на тестовом компьютере, а не замер RTT удалённого VPN-сервера или CPU.
[Действия маршрутизации sing-box](https://sing-box.sagernet.org/configuration/route/rule_action/).

## Отказы и границы восстановления

- При рабочем процессе, DNS-listener и адресном наборе nftables сетевое событие
  не вызывает перезапуск. Во время незавершённого запуска событие также не
  прерывает процесс.
- При выключенном интерфейсе, выключенной службе или занятой операции
  восстановления нет. После неуспешной попытки восстановления сохраняется
  пользовательское `enabled=1`, чтобы следующее сетевое событие могло повторить
  запуск. Штатный procd продолжает контролировать аварийное завершение процесса.
- Явная кнопка «Перезапустить» по-прежнему выполняет полный перезапуск.
- Неизменённое сохранение пропускает перезапуск только при совпадении
  `prepared.sha`: изменения файлов подготовки/службы требуют повторного запуска.
- Последний рабочий список остаётся в ядре при некорректном обновлении;
  сохранённый кэш используется при перезапуске без доступа к источнику.
  RAM-кэш очищается при перезагрузке роутера. Для самого первого получения
  списка нужен доступ к источнику.

Событийное восстановление не подменяет настроенную группу резервных серверов
и не является проверкой каждого активного соединения. Стандартная интеграция
sing-tun с firewall4 использует файл include в `/etc/nftables.d/`, поэтому
разрешающие правила TUN восстанавливаются штатным reload firewall4.

## Воспроизводимые проверки

```sh
npm test -- --test-concurrency=1
python3 scripts/test-openwrt-system.py
sudo unshare -n python3 scripts/test-openwrt-kernel-routing.py /path/to/sing-box-linux-amd64-full
```

Системная проверка выполняется в отдельном rootfs. Проверяются реальный ucode,
UCI, сохранение без перезапуска, обновление файлов приложения, ошибочный запуск,
блокировки, выключенный WAN, сохранение намерения включить службу, запуск и
остановка, APK/IPK и откаты. Netns-проверка использует настоящий nftables/TUN,
IPv4/IPv6, UDP/TCP, FakeIP, JSON/SRS и отказ сервера списков.

На основном роутере проверены неизменённое сохранение, серия сетевых событий,
отсутствие самозапуска после пользовательского отключения, явный повторный
запуск и диагностика 7/7. Физическое отключение WAN в этой итерации не
производилось; отказ источника списков воспроизводился в лаборатории.
