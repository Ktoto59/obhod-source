# Проверка отказоустойчивости

Проверено 6 сентября 2026 года на Windows с ядром
`1.14.0-rc.1-awgm.15`, ревизия `57276220a20679cad762c9644f6abdaf39ab7688`.

## Автоматические проверки

- `npm test`: проверка происхождения ядра, лицензий и модульные/интеграционные тесты.
- `../../test/failover-runtime.test.js`: настоящие процессы sing-box и два локальных
  SOCKS-прокси. После завершения основного запрос проходит через резервный.
  После завершения обоих запрос не проходит напрямую. В группе используется
  `interrupt_exist_connections: false`, как в приложении.
- `../../test/dns-latency.test.js`: локальный DNS перестаёт отвечать; запрос завершается
  по таймауту. После возврата ответов следующая проверка проходит.
- `../../test/recovery-controller.test.js`: события сна и возврата сети, ограничение
  повторных сбоев, ошибка готовности без exit-события, отмена отложенного
  восстановления и ручная остановка во время запуска.
- `../../test/config-generator.test.js`: ядро принимает генерируемые конфигурации,
  включая AmneziaWG, DNS и выборочную маршрутизацию приложений.
- `../../test/backup.test.js`: шифрование копии, неверный пароль, повреждение файла,
  добавление и замена, проверка путей программ и откат при ошибке запуска.
- `npm run test:ui`: навигация, мастер, формы протоколов, помощь, предпросмотр
  домена, отсутствие прокрутки главной и полный цикл экспорта/импорта через IPC
  в изолированном профиле.

Сценарий двух прокси проверяет отказ узлов внутри работающего ядра. Он не
доказывает блокировку трафика Windows при завершении самого ядра или исчезновении
TUN-интерфейса. Системный kill switch в этой работе не реализован.

## Ручная матрица перед выпуском

Проводить с рабочим AmneziaWG-профилем и резервным подключением. Проверять
доступ к выбранному сайту через маршрут, обычному сайту напрямую и локальной сети.

| Сценарий | Ожидаемый результат | Статус |
| --- | --- | --- |
| Сон и пробуждение | Одно восстановление, маршрут снова отвечает | Не выполнен |
| Гибернация | Переподключение после возврата Windows | Не выполнен |
| Смена Wi-Fi | Маршрут восстанавливается после смены сети | Не выполнен |
| Отключение и включение адаптера | Нет бесконечного цикла запусков; после возврата сети маршрут работает | Не выполнен |
| Завершение ядра в TUN | Ограниченные попытки, понятная ошибка при исчерпании | Не выполнен |
| Ручной «Стоп» во время восстановления | Сервис остаётся выключенным | Не выполнен |
| Два недоступных удалённых сервера | Выбранный трафик не выходит напрямую, остальной доступен | Не выполнен |

Автоматические события контроллера не заменяют аппаратные переходы Windows.
RC-ядро требует этой матрицы перед публикацией.
